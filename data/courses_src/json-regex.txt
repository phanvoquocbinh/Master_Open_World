## LESSON json-regex-01 | JSON từ con số 0

### JSON là gì?
• JSON (JavaScript Object Notation) là cách viết dữ liệu dạng chữ mà cả người và máy đều đọc được.
• Giống một tờ phiếu: bên trái là nhãn (key), bên phải là giá trị (value), ở giữa là dấu hai chấm.
• Hầu hết API hiện nay gửi và nhận JSON; nhiều file cấu hình (như package.json) cũng là JSON.
Giải thích từng dòng:
• { mở một object.
• "orderId": "ORD-000123" — key và value đều là chuỗi, nằm trong nháy kép.
• "total": 450000 — số, không có nháy.
• "paid": true — giá trị đúng/sai.
• } đóng object. Các cặp cách nhau bằng dấu phẩy; cặp cuối cùng KHÔNG có dấu phẩy.
~~~json
{
  "orderId": "ORD-000123",
  "customer": "Lan",
  "total": 450000,
  "paid": true
}
~~~

### 6 kiểu dữ liệu trong JSON
• string: "Bàn phím" — chữ trong nháy kép.
• number: 25.5 — số nguyên hoặc thập phân (dùng dấu chấm, không dùng dấu phẩy).
• boolean: true hoặc false — viết thường.
• null: không có giá trị.
• array: [ ... ] — danh sách có thứ tự.
• object: { ... } — nhóm các cặp key–value.
Tester chú ý: "25" (chuỗi) khác 25 (số). API trả sai kiểu dữ liệu so với tài liệu là bug.
~~~json
{
  "name": "Bàn phím",
  "price": 25.5,
  "inStock": true,
  "discount": null,
  "tags": ["pc", "sale"],
  "size": { "width": 44, "height": 13 }
}
~~~

### Object lồng nhau và danh sách object
• customer là object nằm trong object lớn — như phong bì bỏ trong phong bì.
• items là array chứa nhiều object — như các dòng trong một hóa đơn.
• Để lấy sku của món thứ hai: vào items → phần tử thứ hai → sku. Bài sau sẽ viết đường đi này bằng code.
• Thụt lề (indent) chỉ giúp dễ đọc; máy không quan tâm khoảng trắng.
~~~json
{
  "orderId": "ORD-000123",
  "customer": { "name": "Lan", "phone": "0912345678" },
  "items": [
    { "sku": "KB-01", "qty": 1, "price": 25.5 },
    { "sku": "MS-02", "qty": 2, "price": 8 }
  ]
}
~~~

### Quy tắc cú pháp vàng
Đọc từng dòng:
• Key luôn nằm trong nháy kép.
• Chỉ dùng nháy kép, không dùng nháy đơn.
• Không có dấu phẩy sau phần tử cuối cùng.
• true, false, null luôn viết thường.
• Số thập phân dùng dấu chấm.
• JSON chuẩn không cho phép viết comment.
~~~text
SAI                                  ĐÚNG
{ name: "Lan" }                      { "name": "Lan" }
{ 'name': 'Lan' }                    { "name": "Lan" }
{ "a": 1, "b": 2, }                  { "a": 1, "b": 2 }
{ "ok": True }                       { "ok": true }
{ "price": 25,5 }                    { "price": 25.5 }
{ "a": 1 // ghi chú }                { "a": 1 }
~~~

### Lỗi thường gặp
• Illegal trailing comma / Expected double-quoted property name: thừa dấu phẩy cuối object.
• Expecting property name enclosed in double quotes: key dùng nháy đơn hoặc không có nháy.
• Expecting value / Unexpected token 'T': giá trị viết sai, ví dụ True thay cho true.
• "line 3 column 11" chỉ chỗ máy phát hiện lỗi; lỗi thật thường nằm ngay trước vị trí đó.
(Nội dung thông báo có thể khác đôi chút tùy phiên bản Python/Node.)

~~~text
Expecting value: line 1 column 8 (char 7)

SyntaxError: Unexpected token 'T', "{"ok": True}" is not valid JSON
~~~

### Đường đi bằng dấu chấm
• Mỗi dấu chấm nghĩa là "đi vào bên trong".
• Giống địa chỉ nhà: Tỉnh → Huyện → Xã → Thôn.
• Đọc từ trái sang phải; mỗi bước phải tồn tại thì mới đi tiếp được.
• Gõ sai một chữ ở tầng giữa sẽ làm "đứt" cả đường đi.
~~~text
user.name               -> "Lam Thoi"
user.address.city       -> "Vân Thoi 1"
user.address.geo.lat    -> "0.1250"
user.company.name       -> "Xưởng Nếp 1"
user.website.url        -> undefined (website là chuỗi, không có gì bên trong)
user.adress.city        -> LỖI (gõ sai adress, tầng này không tồn tại)
~~~

### Array: đếm từ 0
• Vị trí (index) trong array đánh số từ 0, không phải từ 1 — giống tầng trệt là tầng 0.
• Phần tử cuối có index = số phần tử − 1.
• Lỗi "lệch một" (off-by-one) rất hay gặp: lấy [10] khi chỉ có 10 phần tử.
~~~text
GET http://localhost:3130/users  -> array gồm 10 user

users[0].name     -> "Lam Thoi"       (phần tử đầu tiên)
users[1].name     -> "Vạt Nếp"        (phần tử thứ hai)
users[9].name     -> "Clementina DuBuque"  (phần tử cuối)
users[10]         -> undefined             (không tồn tại)
users.length      -> 10
~~~

### Đọc JSON bằng Python
Cách chạy: lưu thành read_users.py, gõ python read_users.py (không cần cài thêm thư viện).
Giải thích:
• import: nạp hai thư viện có sẵn là json và urllib.request.
• Request(..., headers=...): tạo request kèm User-Agent để server nhận diện công cụ gọi.
• urlopen: gửi request; json.load: chuyển body thành list Python.
• Python dùng ngoặc vuông ["key"] thay cho dấu chấm.
Kết quả mong đợi: 10, Lam Thoi, Deckow-Crist.
~~~python
import json
import urllib.request

url = "http://localhost:3130/users"
req = urllib.request.Request(url, headers={"User-Agent": "qa-course"})
with urllib.request.urlopen(req) as res:
    users = json.load(res)

print(len(users))
print(users[0]["name"])
print(users[1]["company"]["name"])
~~~

## LESSON json-regex-03 | JSONPath: chỉ đường đến dữ liệu

### JSONPath là gì? Dữ liệu mẫu
• JSONPath là cách viết "địa chỉ" để lấy dữ liệu trong JSON, giống GPS chỉ đường.
• Nhiều công cụ dùng JSONPath: JMeter (JSON Extractor), REST Assured, nhiều công cụ giám sát hệ thống.
• Lưu dữ liệu trên thành file shop.json — dùng cho cả bài này.
~~~json
{
  "shop": {
    "name": "QA Store",
    "products": [
      { "id": 1, "name": "Bàn phím", "price": 25, "tags": ["pc"], "inStock": true },
      { "id": 2, "name": "Chuột", "price": 8, "tags": ["pc", "sale"], "inStock": true },
      { "id": 3, "name": "Tai nghe", "price": 40, "tags": ["audio"], "inStock": false },
      { "id": 4, "name": "Cáp USB", "price": 3, "tags": ["sale"], "inStock": true }
    ],
    "owner": { "id": 99, "name": "Lan" }
  }
}
~~~

### Cú pháp cơ bản
• $ là gốc; dấu chấm là "đi vào bên trong".
• [0] lấy phần tử đầu; [*] lấy tất cả phần tử.
• [-1:] lấy phần tử cuối (cú pháp cắt mảng).
• .. là "tìm ở mọi tầng" — tiện nhưng nguy hiểm: $..id lấy cả id của owner (99) dù bạn chỉ muốn id sản phẩm.
Kết quả JSONPath thường là một danh sách, kể cả khi chỉ có 1 giá trị.
Thử bằng script jp.js ở slide kế tiếp trên shop.json do học viên tự tạo; không dán dữ liệu vào website bên ngoài.
~~~text
$                            -> toàn bộ tài liệu (gốc)
$.shop.name                  -> "QA Store"
$.shop.products[0].name      -> "Bàn phím"
$.shop.products[*].name      -> ["Bàn phím", "Chuột", "Tai nghe", "Cáp USB"]
$.shop.products[-1:].name    -> ["Cáp USB"]  (phần tử cuối)
$..id                        -> [1, 2, 3, 4, 99]
~~~

### Bộ lọc (filter)
• [?( ... )] là bộ lọc: chỉ giữ phần tử thỏa điều kiện.
• @ nghĩa là "phần tử đang được xét".
• && là "và", || là "hoặc".
• Chuỗi trong bộ lọc dùng nháy đơn, ví dụ 'Chuột'.
Lưu ý: cú pháp filter có khác biệt nhỏ giữa các công cụ (JMeter hoặc thư viện đang cài). Luôn thử trên đúng công cụ bạn sẽ dùng.
~~~text
$.shop.products[?(@.price < 10)].name                       -> ["Chuột", "Cáp USB"]
$.shop.products[?(@.inStock == false)].name                 -> ["Tai nghe"]
$.shop.products[?(@.price >= 20 && @.inStock == true)].id   -> [1]
$.shop.products[?(@.name == 'Chuột')].price                 -> [8]
~~~

### Chạy JSONPath bằng Node
Lưu thành jp.js rồi chạy node jp.js.
Giải thích từng dòng:
• Dòng 1: nạp hàm JSONPath từ thư viện.
• Dòng 2: đọc file shop.json thành object.
• JSONPath({ path, json }): chạy biểu thức path trên dữ liệu json, trả về một array.
• console.log: in kết quả ra màn hình.
Kết quả mong đợi:
[ 'Bàn phím', 'Chuột', 'Tai nghe', 'Cáp USB' ]

~~~js
const { JSONPath } = require("jsonpath-plus");
const data = require("./shop.json");

const names = JSONPath({ path: "$.shop.products[*].name", json: data });
console.log(names);

const cheap = JSONPath({ path: "$.shop.products[?(@.price < 10)].name", json: data });
console.log(cheap);
~~~

• Nhớ: JSONPath trả về array; muốn lấy giá trị đầu tiên thì dùng names[0].

## LESSON json-regex-04 | Lấy dữ liệu JSON trong Postman và JMeter

### Postman: đi đường bằng JavaScript
• Postman không dùng JSONPath trực tiếp; ta viết đường đi kiểu JavaScript.
• Đối chiếu: JSONPath $[0].address.city tương đương JavaScript users[0].address.city.
• Dán code vào tab Scripts → Post-response, bấm Send, xem tab Test Results.
Kết quả mong đợi: 2 test PASS.
~~~js
// GET http://localhost:3130/users
const users = pm.response.json();

pm.test("User đầu tiên là Lam Thoi", function () {
  pm.expect(users[0].name).to.eql("Lam Thoi");
});

pm.test("User đầu tiên ở Vân Thoi 1", function () {
  pm.expect(users[0].address.city).to.eql("Vân Thoi 1");
});
~~~

### Postman: find, filter, every
• u => ... là hàm ngắn (arrow function): "với mỗi user u, kiểm tra điều kiện...".
• find: phần tử ĐẦU TIÊN thỏa điều kiện (giống bộ lọc JSONPath rồi lấy [0]).
• filter: TẤT CẢ phần tử thỏa điều kiện (giống [?( ... )] của JSONPath).
• every: mọi phần tử đều thỏa thì trả về true.
Kết quả mong đợi: 3 test PASS.
~~~js
const users = pm.response.json();

const user2 = users.find(u => u.username === "Antonette");
const firstThree = users.filter(u => u.id <= 3);

pm.test("Tìm thấy user Antonette có id 2", () => {
  pm.expect(user2).to.not.be.undefined;
  pm.expect(user2.id).to.eql(2);
});

pm.test("Lọc được 3 user đầu", () => {
  pm.expect(firstThree).to.have.lengthOf(3);
});

pm.test("Mọi email đều có @", () => {
  pm.expect(users.every(u => u.email.includes("@"))).to.be.true;
});
~~~

### Lưu giá trị để request sau dùng (correlation)
Request tiếp theo: GET {{baseUrl}}/posts/{{firstPostId}}/comments
Giải thích từng dòng:
• Dòng 1: comment ghi request nào dùng script này.
• Dòng 2: đọc danh sách bài viết của user 1.
• Dòng 3: lưu id bài đầu tiên vào biến collection firstPostId (giá trị 1).
• Dòng 4: lưu số bài viết (10) để đối chiếu sau.
Lấy dữ liệu từ response trước để dùng cho request sau gọi là correlation — kỹ năng bắt buộc khi test API và test hiệu năng.
~~~js
// GET {{baseUrl}}/posts?userId=1
const posts = pm.response.json();
pm.collectionVariables.set("firstPostId", posts[0].id);
pm.collectionVariables.set("postCount", posts.length);
~~~

### JMeter: JSON Extractor
Thêm extractor: chuột phải vào HTTP Request → Add → Post Processors → JSON Extractor.
• Names of created variables: tên biến JMeter sẽ tạo.
• JSON Path expressions: biểu thức JSONPath; dùng $[0].id vì response là một array.
• Match No.: 1 = lấy kết quả thứ nhất.
• Default Values: giá trị khi không tìm thấy — đặt NOT_FOUND để dễ phát hiện lỗi.
• Request sau dùng biến bằng cú pháp ${firstUserId}.
~~~text
Thread Group
 ├─ HTTP Request: GET http://localhost:3130/users
~~~

## LESSON json-regex-05 | Regex căn bản: khuôn dò chữ

### Regex là gì?
• Regex (regular expression, biểu thức chính quy) là "khuôn" để dò tìm chữ.
• Giống Ctrl+F nhưng có ký tự đại diện: "một chữ số bất kỳ", "lặp lại 6 lần"...
• Tester dùng regex để: kiểm tra định dạng (email, mã đơn), trích xuất dữ liệu (token, id) từ response, lọc file log.
~~~text
Mẫu (pattern)     Khớp với
cat               "cat", "concat", "category"
\d\d\d            "123", "phòng 405"
ORD-\d{6}         "ORD-000123"
^0\d{9}$          "0912345678" (cả chuỗi là 1 số điện thoại 10 số)
~~~

### Các ký tự đặc biệt
• \D, \W, \S (viết hoa) là phủ định của \d, \w, \s.
• Ví dụ: [A-Z]\d khớp "B7", không khớp "b7".
• Lưu ý: trong JavaScript, \w chỉ gồm chữ không dấu (a-z, A-Z), số và _; trong Python, \w mặc định khớp cả chữ có dấu như "ữ".
~~~text
.        một ký tự bất kỳ (trừ xuống dòng)
\d       một chữ số 0-9
\w       một chữ cái, chữ số hoặc dấu _
\s       một khoảng trắng (space, tab, xuống dòng)
[abc]    một trong các ký tự a, b, c
[0-9]    một chữ số (giống \d)
[A-Z]    một chữ in hoa không dấu
[^0-9]   một ký tự KHÔNG phải chữ số
\.       dấu chấm thật (thêm \ để "tắt" ý nghĩa đặc biệt)
~~~

### Lượng từ: lặp bao nhiêu lần?
• Lượng từ (quantifier) đứng SAU thứ nó áp dụng: \d{6} = "chữ số, lặp 6 lần".
• colou?r khớp cả "color" và "colour".
• Mặc định lượng từ "tham lam" (greedy) — lấy nhiều nhất có thể. Bài 7 sẽ nói về cái bẫy này.
~~~text
a+        1 hoặc nhiều chữ a          "a", "aaa"
a*        0 hoặc nhiều chữ a          "", "aaaa"
a?        0 hoặc 1 chữ a              "", "a"
\d{6}     đúng 6 chữ số               "000123"
\d{2,4}   từ 2 đến 4 chữ số           "12", "1234"
\d{3,}    từ 3 chữ số trở lên         "123", "1234567"
~~~

### Neo, lựa chọn và nhóm
• ^ và $ là "neo": ghim mẫu vào đầu và cuối chuỗi. Không có neo, \d{6} vẫn khớp với "abc1234567xyz".
• | nghĩa là "hoặc".
• ( ) gom nhóm và "bắt" phần khớp để lấy ra dùng (capturing group).
• Khi kiểm tra định dạng (validation), gần như luôn cần ^ ... $.
~~~text
^ORD                  chuỗi phải BẮT ĐẦU bằng ORD
\d$                   chuỗi phải KẾT THÚC bằng một chữ số
^\d{6}$               toàn bộ chuỗi là đúng 6 chữ số
PAID|SHIPPED          PAID hoặc SHIPPED
^(PAID|SHIPPED)$      cả chuỗi là PAID hoặc SHIPPED
(\d{4})-(\d{2})       nhóm 1 = năm, nhóm 2 = tháng
~~~

### Luyện regex ngay trong Node hoặc DevTools lab
Mở Node REPL trong thư mục lab hoặc DevTools của localhost, dùng regex JavaScript để tìm mã trong chuỗi tự đặt. Ví dụ trả đúng ORD-000123,không lấy ORD-12 thiếu số. Flagg tìm tất cả,i bỏ phân biệt hoa/thường,m thay cách neo theo dòng;đối chiếu engine thực dùng vì cú pháp không giống nhau hoàn toàn. Không tải dữ liệu lên công cụ công khai.
~~~js

console.log([...text.matchAll(/ORD-\d{6}/g)].map(x=>x[0]));
// ['ORD-000123']
~~~

### Lỗi thường gặp
• Quên escape: . + ? * ( ) [ ] { } ^ $ | \ là ký tự đặc biệt; muốn tìm đúng ký tự đó phải thêm \ phía trước. Trong JavaScript, dấu / cũng cần viết \/.
• Quên neo ^ $: regex chỉ khớp một phần nên dữ liệu sai vẫn "pass".
• Sai flavor: regex chạy đúng trên mẫu Python nhưng sai trong JavaScript → chọn đúng flavor của công cụ bạn dùng.
• Regex quá dài, không ai đọc nổi → tách nhỏ và ghi chú giải thích.
~~~text
Regex: example.com     khớp nhầm "exampleXcom"      -> sửa: example\.com
Regex: \d{10}          khớp nhầm "a12345678901b"    -> sửa: ^\d{10}$
Regex: \d{2}/\d{2}     regex literal JavaScript báo: An unescaped delimiter must be escaped
~~~

### Python: re.findall và re.search

Giải thích:

## LESSON json-regex-07 | Trích xuất bằng nhóm và bẫy greedy/lazy

### Nhóm ( ): bắt đúng phần cần lấy
• Phần nằm trong ngoặc ( ) là thứ ta muốn "bắt" lấy.
• [^"]+ = một hoặc nhiều ký tự không phải dấu nháy kép → dừng đúng tại dấu " kết thúc giá trị.
• Nhóm 0 là toàn bộ phần khớp; nhóm 1, 2... là các ngoặc tính từ trái sang phải.
• Ứng dụng: lấy token ẩn trong trang HTML, lấy mã đơn trong tin nhắn, lấy id trong header Location.
~~~text
Chuỗi  : <input type="hidden" name="csrf_token" value="a1b2c3d4e5">
Regex  : name="csrf_token" value="([^"]+)"
Nhóm 0 : name="csrf_token" value="a1b2c3d4e5"
Nhóm 1 : a1b2c3d4e5
~~~

### Trích xuất bằng JavaScript
Giải thích từng dòng:
• Dòng 1–2: dữ liệu mẫu — một đoạn HTML và giá trị của header Location.
• Dòng 4–5: match trả về mảng; phần tử [1] là nhóm thứ nhất.
• \/ là dấu / đã được escape, vì trong JavaScript dấu / dùng để bao regex.
• csrf ? csrf[1] : "...": nếu tìm thấy thì in nhóm 1, nếu không (null) thì in thông báo — tránh lỗi đọc null.
Kết quả mong đợi: a1b2c3d4e5 và ORD-000777.
~~~js
const html = '<form><input type="hidden" name="csrf_token" value="a1b2c3d4e5"></form>';
const locationHeader = "/api/orders/ORD-000777";

const csrf = html.match(/name="csrf_token" value="([^"]+)"/);
const order = locationHeader.match(/\/orders\/(ORD-\d{6})$/);

console.log(csrf ? csrf[1] : "Không tìm thấy token");
console.log(order ? order[1] : "Không tìm thấy mã đơn");
~~~

### Greedy và lazy: tham lam hay vừa đủ?
Kết quả mong đợi:
Giá</b> và <b>Số lượng
Giá
• .* là tham lam (greedy): ăn nhiều nhất có thể, chạy tới </b> CUỐI CÙNG.
• .*? là lười (lazy): dừng ở </b> GẦN NHẤT.
• Khi trích xuất giá trị nằm giữa hai dấu mốc, nên dùng .*? hoặc [^<]+ thay vì .*
~~~js
const html = "<b>Giá</b> và <b>Số lượng</b>";

console.log(html.match(/<b>(.*)<\/b>/)[1]);
console.log(html.match(/<b>(.*?)<\/b>/)[1]);
~~~

### Python: nhóm có tên để đọc log
• (?P<tên>...): nhóm có tên (named group) trong Python — dễ đọc hơn nhóm số 1, 2, 3.
• .* ở giữa: bỏ qua phần giờ và mức log.
• Ứng dụng: quét file log hàng nghìn dòng để tìm mọi đơn lỗi PAYMENT_TIMEOUT.
Kết quả mong đợi: 2025-05-04, ORD-000777, PAYMENT_TIMEOUT.
Trong JavaScript, nhóm có tên viết là (?<tên>...) — không có chữ P.
~~~python
import re

line = "2025-05-04 10:15:32 ERROR order=ORD-000777 code=PAYMENT_TIMEOUT"
pattern = r"^(?P<date>\d{4}-\d{2}-\d{2}) .*order=(?P<order>ORD-\d{6}) code=(?P<code>\w+)"

m = re.search(pattern, line)
if m:
    print(m.group("date"))
    print(m.group("order"))
    print(m.group("code"))
~~~

### JMeter: Regular Expression Extractor

• Match No. 1: lấy kết quả khớp đầu tiên.
• Default Value: giá trị khi không khớp — giúp phát hiện lỗi ngay.
• Response là JSON thì ưu tiên JSON Extractor; Regular Expression Extractor hợp với HTML, header, text thường.

### Lỗi thường gặp và khi nào KHÔNG nên dùng regex
Kết quả mong đợi: abc.def.ghi
• Regex cho JSON rất dễ vỡ: chỉ cần server thêm khoảng trắng ("token": "...") là regex trên hết khớp. Dữ liệu JSON thì dùng JSON.parse hoặc JSONPath.
• TypeError: Cannot read properties of null (reading '1'): regex không khớp nên match trả về null → luôn kiểm tra trước khi lấy [1].
• Biến JMeter ra CSRF_NOT_FOUND: regex khác response lab (dấu cách, thứ tự thuộc tính) → dùng đúng đoạn response giả trong Node REPL để thử bằng RegExp; với response HTML phức tạp cân nhắc parser thay regex.
• Regex lồng lượng từ như (a+)+ có thể chạy cực lâu với chuỗi dài (catastrophic backtracking) → giữ regex đơn giản.
~~~js
const body = '{"user":"demo","token":"abc.def.ghi"}';

// Không nên: dùng regex để đọc JSON
const m = body.match(/"token":"(.+?)"/);

// Nên: dùng JSON.parse
const token = JSON.parse(body).token;
console.log(token);
~~~

## LESSON json-regex-08 | Schema và validate ở ranh giới API

### Schema kiểm hình dạng tại cửa vào
Kho giả định Tơ Nâu nhận id chuỗi không rỗng và qty nguyên dương. Phiên bản lab từ chối trường lạ; đổi chính sách phải xem tương thích client, không chỉ sửa mẫu thành công.
~~~json
{"type":"object","required":["id","qty"],"properties":{"id":{"type":"string","minLength":1},"qty":{"type":"integer","minimum":1}},"additionalProperties":false}
~~~

### Hiện diện và giá trị là hai trục
Ba payload dưới bị từ chối vì thiếu trường, sai kiểu hoặc ngoài miền. Nếu cho phép null, viết rõ union kiểu và quyết định nghĩa nghiệp vụ; required không tự giải quyết điều này.
~~~text
{}
{"id":"K2","qty":null}
{"id":"K2","qty":0}
~~~

### Validator thay tự đoán toàn bộ chuẩn
Ajv là công cụ mã nguồn mở. Biên dịch schema cục bộ một lần rồi kiểm nhiều payload; ví dụ không tải schema qua mạng và cần pin phiên bản dependency trong lab.
~~~js
import Ajv from 'ajv';
const ajv=new Ajv({allErrors:true});
const schema={type:'object',required:['qty'],properties:{qty:{type:'integer',minimum:1}},additionalProperties:false};
const valid=ajv.compile(schema);
console.log(valid({qty:0}),valid.errors);
~~~

### Đúng shape chưa đủ đúng giao dịch
qty hợp kiểu vẫn có thể vượt tồn kho hoặc thuộc đơn người khác. Sau kiểm shape phải kiểm quyền và nghiệp vụ; không cố biến regex id thành cơ chế cấp quyền.

### Tạo ca âm có ý nghĩa
Kiểm trường lạ, id rỗng, qty lẻ và trường thiếu, mỗi ca chỉ nhắm một lý do. Ghi instancePath/keyword cùng expected để biết validator đang chặn đúng điều kiện.

PRACTICE: Tạo lab Node ESM dùng Ajv với schema cục bộ và tám payload tự viết. Chạy cả tốt/xấu, báo path và keyword, tách quy tắc tồn kho khỏi schema.
Q: Schema có thay kiểm quyền không?
+ Không
- Có nếu chuỗi ngắn
- Có nếu không có NULL
Q: required khác nullable thế nào?
+ Hiện diện khác cho phép null
- required luôn cấm null
- Cho null luôn cho thiếu

## LESSON json-regex-09 | Unicode, chuẩn hóa và cách đếm ký tự

### Đơn vị độ dài cần theo sản phẩm
Nhãn giả định giới hạn ký tự người đọc thấy. length đếm UTF-16, spread đếm code point; chữ có dấu tổ hợp có thể là nhiều code point trong một grapheme.
~~~js
const s='á';
console.log(s.length,[...s].length); // 2,2
console.log(s.normalize('NFC').length); // 1 với ví dụ này
~~~

### NFC cho tương đương chuẩn tắc
Chuẩn hóa có thể hỗ trợ so hai cách nhập cùng chữ, không phải sửa chính tả hay bỏ dấu. Chỉ áp cho trường đã có quy định, giữ bản gốc nếu cần hiển thị hoặc đối chiếu.
~~~js
const a='á',b='á';
console.assert(a!==b);
console.assert(a.normalize('NFC')===b.normalize('NFC'));
~~~

### Tách ngân sách byte và ký tự
Intl.Segmenter chia grapheme trên runtime hỗ trợ. Byte phục vụ giới hạn truyền/lưu, grapheme phục vụ một số yêu cầu hiển thị; cần test emoji và dấu kết hợp theo chính sách.
~~~js
const seg=new Intl.Segmenter('vi',{granularity:'grapheme'});
const count=s=>[...seg.segment(s)].length;
console.log(count('á'));
console.log(new TextEncoder().encode('á').length);
~~~

### Bẫy chuẩn hóa toàn hệ thống
NFKC có thể gộp khác biệt hình thức có ý nghĩa. Không áp chỉ để test xanh; quy tắc tìm kiếm có thể khác quy tắc lưu nội dung và xác định danh tính.

### Bảng nhập dấu của người Việt
Dùng chữ dựng sẵn, dấu tổ hợp, emoji nối, khoảng trắng cuối và xuống dòng. Ghi expected từng đơn vị và kiểm max-1/max/max+1 theo tiêu chí thực tế.

PRACTICE: Viết hàm đếm grapheme, so NFC với sáu chuỗi tự tạo. Bàn giao bảng byte/code point/grapheme và chính sách lưu nguyên bản; kiểm runtime có Intl.Segmenter.
Q: Hai chữ nhìn giống có thể khác mã vì sao?
+ Dựng sẵn và dấu tổ hợp Unicode
- Unicode chỉ có ASCII
- Màn hình sửa mã
Q: JavaScript length đếm đơn vị gì?
+ Đơn vị mã UTF-16
- Luôn số chữ nhìn thấy
- Byte UTF-8

## LESSON json-regex-10 | Regex chậm, giới hạn input và parser thay thế

### Nhận diện mẫu có nhiều cách phân tách
Nhóm lặp lồng nhóm lặp có thể chậm mạnh khi gần khớp rồi hỏng cuối. Chỉ nhận diện mẫu và thử input nhỏ, không tăng chuỗi vô hạn để chứng minh bằng cách làm treo máy.
~~~js
// Chỉ xem cấu trúc rủi ro:
const source='^(a+)+$';
const simpler=/^a+$/;
console.log(simpler.test('aaaa'));
~~~

### Giới hạn nguồn trước phép khớp
Mã lab có tiền tố LAB- và tối đa hai mươi ký tự ASCII sau đó. Kiểm kiểu/độ dài trước regex; con số là chính sách ví dụ, không phải chuẩn áp dụng mọi sản phẩm.
~~~js
function validCode(s){
 if(typeof s!=='string'||s.length>24)return false;
 return /^LAB-[A-Z0-9]{1,20}$/.test(s);
}
console.assert(validCode('LAB-A3'));
~~~

### Parser cho cấu trúc lồng
Regex không phải lựa chọn phù hợp để đọc JSON có escape và object lồng. Giới hạn byte rồi JSON.parse, sau đó kiểm shape và miền; lỗi parse không được biến thành object rỗng thành công.
~~~js
function read(s){
 if(new TextEncoder().encode(s).length>4096)throw new Error('too_large');
 const x=JSON.parse(s);
 if(x===null||Array.isArray(x)||typeof x!=='object')throw new Error('object_required');
 return x;
}
~~~

### Timer cùng luồng không bảo đảm ngắt
Regex JavaScript đồng bộ có thể chặn event loop. setTimeout cùng luồng không chắc ngắt được phép khớp đang chạy; ưu tiên mẫu đơn giản và môi trường đo có giới hạn tài nguyên riêng.

### Finding cần phương án sửa cụ thể
Nêu pattern, dạng input gần khớp, tác động và cách thay bằng parser hoặc mẫu nhỏ. Một lần chạy nhanh không đủ kết luận an toàn, lazy cũng không tự xóa mọi nguy cơ.

PRACTICE: Review năm mẫu tự đặt, viết lại hai mẫu và thêm giới hạn input. Dùng test gần khớp nhỏ, giải thích khi nào chọn parser; không benchmark tải tăng không giới hạn.
Q: Lượng từ lồng gần khớp có thể gây gì?
+ Backtracking tốn tài nguyên
- Luôn thời gian hằng số
- Chỉ lỗi cú pháp
Q: Kiểm email sơ bộ nên dựa vào gì?
+ Quy tắc sản phẩm và luồng xác minh
- Một regex dài là đủ
- Chỉ có ký tự @

## LESSON json-regex-11 | Đọc JSON lớn và phản hồi lỗi có đường dẫn

### Chốt giao thức NDJSON
Mỗi dòng không rỗng là một object JSON độc lập theo quy ước lab. Không split một JSON array nhiều dòng bất kỳ; producer phải cam kết cách mã hóa record.
~~~text

{"id":"N2","qty":0}
{"id":"N3","qty":4}
~~~

### Đọc luồng vẫn cần kiểm tài nguyên
readline hỗ trợ CRLF nhưng không tự đặt ngân sách chiều dài một dòng. Ví dụ cần thêm giới hạn file và record ở lớp nhập; thu lỗi không đồng nghĩa import được báo thành công.
~~~js
import {createReadStream} from 'node:fs';
import {createInterface} from 'node:readline';
const rl=createInterface({input:createReadStream('input.ndjson'),crlfDelay:Infinity});
let n=0;
for await(const line of rl){
 n++;if(!line.trim())continue;
 try{console.log(n,JSON.parse(line).id);}
 catch{console.error(`line ${n}: invalid_json`);}
}
~~~

### Vị trí lỗi vừa đủ để sửa
Báo số dòng nguồn và path trong record, không dump nguyên dữ liệu riêng tư. Code ổn định giúp tổng hợp số lỗi theo loại và dịch thông báo thân thiện ở giao diện.
~~~json

~~~

### Thu đủ lỗi hay dừng phải có chính sách
Có thể thu lỗi rồi từ chối cả lô hoặc xử lý dòng tốt nếu sản phẩm cho phép. Công khai tính nguyên tử; nếu stream bị cắt giữa chừng, không báo như đã kiểm toàn file.

### Kiểm biên của luồng đọc
Fixture gồm file rỗng, dòng cuối thiếu newline, CRLF, JSON hỏng và lỗi đọc giả lập. Ghi hành vi mong đợi mỗi ca để phân biệt đầu vào không hợp lệ với nguồn không đọc được.

PRACTICE: Xây CLI báo dòng/path, chỉ hiển thị tối đa hai mươi lỗi nhưng tổng hợp đủ số lỗi. Kiểm file trống và dòng cuối thiếu newline, ghi giới hạn file/record và tính nguyên tử.

## LESSON json-regex-12 | So sánh hợp đồng: thiếu, null và khác thứ tự

### So dữ liệu theo nghĩa hợp đồng
Object lab được coi là ánh xạ, array giữ thứ tự hiển thị. Serialize trực tiếp có thể khác vì thứ tự khóa; tự sort mọi array lại có thể che lỗi thứ tự nghiệp vụ.
~~~js
const a={id:'R1',qty:2},b={qty:2,id:'R1'};
console.log(JSON.stringify(a)===JSON.stringify(b)); // false
~~~

### Không xóa khác biệt null và thiếu
hasOwn kiểm trường có thật trên object. Xóa null trước so sánh có thể làm thay đổi hợp đồng bị bỏ lọt; optional và nullable phải có test riêng.
~~~js
const a={},b={note:null};
console.log(Object.hasOwn(a,'note')); // false
console.log(Object.hasOwn(b,'note')); // true
~~~

### Báo diff ngắn có đường dẫn
Mỗi khác biệt có path và loại lỗi. Che dữ liệu riêng tư ở báo cáo theo chính sách, không sửa comparator để coi mọi giá trị nhạy cảm là giống nhau.
~~~json
[{"path":"$.items[1].qty","kind":"changed","expected":2,"actual":3},{"path":"$.note","kind":"missing"}]
~~~

### Chuẩn hóa số và ngày có điều kiện
1 và 1.0 cùng là number sau parse nhưng "1" khác 1. Chỉ quy hai chuỗi giờ về cùng instant khi hợp đồng cho phép; không bỏ múi giờ để test xanh.

### Kiểm chính công cụ so sánh
Expected phải viết tay cho khóa đảo, array đảo, null/thiếu và object lồng. Comparator lỗi có thể khiến cả bộ test xanh sai, nên test âm phải chứng minh từng loại lệch bị phát hiện.

PRACTICE: Viết comparator giới hạn cho JSON lab và sáu cặp fixture. Xuất diff có path, nêu chính sách object/array/null/số/ngày và loại cấu trúc chưa hỗ trợ.

## LESSON json-regex-13 | Dự án: bộ kiểm dữ liệu nhập từ file

### Luồng import chỉ tạo báo cáo
Xưởng giả định Lụa Vang cần kiểm trước khi nạp kho. Dự án không tự sửa nguồn hay kết nối dữ liệu công việc; trạng thái từng tầng giúp xác định lỗi đọc, cú pháp, shape hoặc trùng mã.
~~~text
nguồn -> giới hạn byte -> đọc dòng -> parse
      -> kiểm shape -> kiểm trùng -> báo cáo
Trạng thái: OK / INVALID_INPUT / READ_ERROR
Không biến đổi input.
~~~

### Regex nhỏ cho mã có quy tắc rõ
id lab là SP- cộng một đến mười hai ký tự ASCII hoa hoặc số, qty nguyên không âm. Tên Unicode đi qua quy tắc riêng, không dồn mọi yêu cầu vào cùng regex.
~~~js
function checkRow(x){
 if(!x||typeof x!=='object'||Array.isArray(x))return ['object_required'];
 const e=[];
 if(typeof x.id!=='string'||!/^SP-[A-Z0-9]{1,12}$/.test(x.id))e.push('id_invalid');
 if(!Number.isInteger(x.qty)||x.qty<0)e.push('qty_invalid');
 return e;
}
~~~

### Lưu lần xuất hiện đầu khi tìm trùng
Map lưu dòng đầu để khi gặp trùng chỉ được cả hai vị trí. Không ghi đè ngay khi gặp id mới, vì người sửa cần đầu mối đối chiếu thay vì chỉ biết mã bị trùng.
~~~js
const seen=new Map();
function duplicate(id,line){
 if(seen.has(id))return {id,firstLine:seen.get(id),line};
 seen.set(id,line);return null;
}
~~~

Tạo mười fixture gồm trùng mã, ký tự lạ, qty null/âm, dấu tổ hợp và JSON hỏng. Expected tách khỏi hàm kiểm; tạm phá một điều kiện để chứng minh test đủ nhạy.

Nộp Node ESM, dữ liệu tự viết, báo cáo, exit code và checksum input trước/sau. Công khai giới hạn bộ nhớ, số record và loại lỗi chưa kiểm; không coi lab là chứng nhận an toàn.
