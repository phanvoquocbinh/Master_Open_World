## LESSON selenium-01 | Selenium là gì và chuẩn bị môi trường Python

### Selenium là gì?
Hãy tưởng tượng trình duyệt là một chiếc xe hơi, còn bạn ngồi ghế sau đọc chỉ dẫn: "rẽ trái, dừng ở cổng số 3".
• Selenium WebDriver là "người tài xế": nhận lệnh từ code của bạn và điều khiển trình duyệt thật (Chrome, Edge, Firefox).
• Code Python của bạn gửi lệnh → WebDriver (ví dụ chromedriver) → trình duyệt làm theo.
• Selenium ra đời từ lâu, được dùng ở rất nhiều công ty, hỗ trợ nhiều ngôn ngữ (Java, Python, C#, JavaScript).
• Khóa này dùng Python vì cú pháp gần với tiếng Anh, dễ đọc cho người mới.
Bạn sẽ học: mở trang, tìm phần tử, bấm, gõ, chờ, kiểm tra kết quả và tổ chức test gọn gàng.

### Bước 0: Kiểm tra Python và pip
Mở PowerShell và gõ:
Giải thích từng dòng:
• python --version: hỏi phiên bản Python. Kết quả mong đợi dạng Python 3.12.x (3.9 trở lên đều được).
• pip --version: hỏi phiên bản pip, công cụ cài thư viện Python. Kết quả dạng pip 24.x from ...
Nếu gõ python mà Microsoft Store bật lên: Python chưa được cài đúng. Cài lại từ trang chính thức của Python và nhớ tick "Add python.exe to PATH" (xem phòng 101).

### Bước 1: Tạo thư mục và môi trường ảo (venv)
Môi trường ảo giống như một "hộp đồ nghề riêng" cho từng dự án: thư viện cài trong hộp này không lẫn sang dự án khác.
Giải thích từng dòng:
• mkdir selenium-hoc: tạo thư mục dự án.
• cd selenium-hoc: đi vào thư mục đó.
• python -m venv .venv: tạo môi trường ảo trong thư mục con tên .venv.
• .venv\Scripts\activate: bật môi trường ảo. Thành công khi đầu dòng lệnh có chữ (.venv).
Mỗi lần mở terminal mới, bạn phải chạy lại lệnh activate.
~~~bash
mkdir selenium-hoc

python -m venv .venv
.venv\Scripts\activate
~~~

### Selenium Manager: không cần tự tải driver nữa
Trước đây, người mới hay "khóc" vì phải tự tải chromedriver.exe đúng phiên bản Chrome.
Từ Selenium 4.6, có sẵn Selenium Manager:
• Khi bạn tạo webdriver.Chrome(), Selenium tự kiểm tra Chrome trên máy và tự tải driver phù hợp.
• Driver được lưu trong thư mục cache của người dùng (thường là C:\Users\<tên bạn>\.cache\selenium).
• Lần chạy đầu có thể chậm vài giây vì phải tải, các lần sau nhanh hơn.
Điều kiện: máy cần có trình duyệt (Chrome hoặc Edge) và có mạng ở lần chạy đầu. Nếu công ty chặn mạng, hỏi IT về proxy.

### Giải thích từng dòng
• from selenium import webdriver: lấy module webdriver từ thư viện selenium.
• driver = webdriver.Chrome(): mở một cửa sổ Chrome mới do code điều khiển. Biến driver là "tài xế" của ta.
• driver.get(...): đi tới địa chỉ web và chờ trang tải xong phần chính.
• driver.title: đọc tiêu đề trang (chữ trên tab trình duyệt).
• driver.current_url: đọc địa chỉ hiện tại.
• print(...): in ra màn hình terminal.
• driver.quit(): đóng trình duyệt và tắt driver. Luôn nhớ quit, nếu không máy sẽ còn nhiều tiến trình chrome chạy ngầm.

### Dùng trình duyệt khác và giữ cửa sổ để quan sát
Giải thích từng dòng:
• import time: lấy module thời gian của Python.
• webdriver.Edge(): mở Microsoft Edge (có sẵn trên Windows). Tương tự có webdriver.Firefox() nếu máy cài Firefox.
• maximize_window(): phóng to cửa sổ hết màn hình.
• time.sleep(3): dừng 3 giây để bạn kịp nhìn. CHỈ dùng khi học; trong test thật sẽ dùng cách chờ thông minh (bài 5).
• driver.quit(): đóng trình duyệt.
~~~python
import time
from selenium import webdriver

driver = webdriver.Edge()
driver.maximize_window()
driver.get("http://localhost:3131/")
time.sleep(3)
driver.quit()
~~~

### Lỗi thường gặp
• Lỗi 1: bạn đặt tên file là selenium.py, Python nhầm file của bạn với thư viện. Đổi tên file (ví dụ first_script.py) và xóa thư mục __pycache__ nếu có.
• Lỗi 2: phiên bản driver và trình duyệt lệch nhau, thường do có chromedriver.exe cũ nằm trong PATH. Xóa file driver cũ khỏi PATH, rồi nâng Selenium: pip install -U selenium.
• Lỗi 3: Selenium Manager không tải được driver (mất mạng, bị proxy chặn) hoặc máy chưa cài trình duyệt. Kiểm tra mạng, cài Chrome hoặc dùng webdriver.Edge().

## LESSON selenium-03 | Tìm phần tử: ID, NAME, CSS và XPath

### Xem "giấy khai sinh" của phần tử bằng DevTools
Mỗi phần tử trên trang (ô nhập, nút) được viết bằng HTML. Muốn Selenium tìm đúng, ta phải đọc HTML của nó.
Cách làm: mở http://localhost:3131/login → chuột phải vào ô Username → Inspect (hoặc nhấn F12).
Giải thích từng dòng:
• Dòng 1: ô nhập chữ, có id="username" và name="username".
• Dòng 2: ô mật khẩu, id="password".
• Dòng 3: nút Login, có class="radius" và type="submit".
id giống số căn cước: thường là duy nhất trên trang, nên được ưu tiên dùng.
~~~xml
<input type="text" name="username" id="username">
<input type="password" name="password" id="password">
<button class="radius" type="submit"><i class="fa fa-2x fa-sign-in"> Login</i></button>
~~~

### Các cách tìm với By
Giải thích từng dòng:
• from selenium.webdriver.common.by import By: lấy "danh sách cách tìm" By.
• By.ID, "username": tìm theo id.
• By.NAME, "password": tìm theo thuộc tính name.
• By.CSS_SELECTOR, "button[type='submit']": tìm thẻ button có type là submit.
• By.XPATH, "//h2": tìm thẻ h2 ở bất kỳ đâu trên trang.
• title.text: lấy chữ hiển thị. Kết quả in ra: Lab Login
Ngoài ra còn By.LINK_TEXT, By.PARTIAL_LINK_TEXT, By.CLASS_NAME, By.TAG_NAME.
~~~python
from selenium import webdriver
from selenium.webdriver.common.by import By

driver = webdriver.Chrome()
driver.get("http://localhost:3131/login")
user = driver.find_element(By.ID, "username")
pwd = driver.find_element(By.NAME, "password")
btn = driver.find_element(By.CSS_SELECTOR, "button[type='submit']")
title = driver.find_element(By.XPATH, "//h2")
print(title.text)
driver.quit()
~~~

### Bảng tóm tắt CSS selector
Giải thích:
• Dấu # nghĩa là id, dấu chấm nghĩa là class.
• [thuộc tính='giá trị'] lọc theo thuộc tính bất kỳ.
• Khoảng trắng nghĩa là "nằm bên trong (ở mọi cấp)", dấu > là "con trực tiếp".
Thử nhanh: trong DevTools nhấn Ctrl+F ở tab Elements, gõ selector, DevTools sẽ cho biết khớp mấy phần tử (ví dụ 1 of 1).
~~~text
#username                 phần tử có id="username"
.radius                   phần tử có class="radius"
input[name='password']    thẻ input có name="password"
button[type='submit']     thẻ button có type="submit"
#checkboxes input         thẻ input nằm BÊN TRONG phần tử id="checkboxes"
ul > li                   thẻ li là con trực tiếp của ul
li:nth-child(2)           thẻ li đứng thứ 2 trong cha của nó
~~~

### Bảng tóm tắt XPath
Giải thích:
• // là "tìm ở bất kỳ đâu", @ là thuộc tính, text() là chữ của chính thẻ đó.
• contains(., 'Login'): dấu chấm nghĩa là toàn bộ chữ bên trong phần tử, khớp một phần.
• XPath mạnh khi phải tìm theo chữ hoặc đi ngược lên cha, nhưng dài và dễ gãy. Ưu tiên: ID → NAME → CSS → XPath.
• Tránh XPath tuyệt đối kiểu /html/body/div[2]/div/div/form: chỉ cần trang thêm một thẻ div là hỏng.
~~~text
//input[@id='username']               thẻ input có id="username"
//button[@type='submit']              nút có type="submit"
//a[text()='Elemental Selenium']      thẻ a có chữ đúng bằng "Elemental Selenium"
//button[contains(., 'Login')]        nút có chứa chữ "Login" (kể cả trong thẻ con)
//form[@id='login']//input            mọi input nằm trong form id="login"
(//input)[2]                          thẻ input thứ 2 trên trang
~~~

### find_element và find_elements khác nhau thế nào?
Giải thích từng dòng:
• find_elements (có chữ s): trả về DANH SÁCH mọi phần tử khớp.
• len(boxes): đếm số phần tử. Kết quả: Số checkbox: 2
• for box in boxes: lặp qua từng checkbox, is_selected() cho biết đã tick chưa. Kết quả: False rồi True.
• Tìm phần tử không tồn tại bằng find_elements: KHÔNG lỗi, chỉ trả danh sách rỗng, len = 0.
• Còn find_element (không có s): trả MỘT phần tử đầu tiên khớp, nếu không có sẽ báo lỗi ngay.
~~~python
from selenium import webdriver
from selenium.webdriver.common.by import By

driver = webdriver.Chrome()
driver.get("http://localhost:3131/checkboxes")
boxes = driver.find_elements(By.CSS_SELECTOR, "#checkboxes input")
print("Số checkbox:", len(boxes))
for box in boxes:
    print(box.is_selected())
none = driver.find_elements(By.ID, "khong-ton-tai")
~~~

## LESSON selenium-05 | Chờ đợi đúng cách: implicit và explicit wait

### Vì sao phải chờ?
Trang web hiện đại tải từng phần: khung trang hiện trước, dữ liệu tới sau.
Code Selenium chạy rất nhanh, nhanh hơn trang web. Nếu tìm phần tử khi nó chưa xuất hiện sẽ bị NoSuchElementException.
Ví dụ đời thường: gọi món ở quán ăn, bạn không thể ăn ngay giây tiếp theo, phải chờ món được bưng ra.
Ba cách chờ:
• time.sleep(n): chờ cứng n giây. Dễ nhưng tệ.
• Implicit wait: đặt một lần, mọi lệnh find_element đều kiên nhẫn chờ tối đa n giây.
• Explicit wait: chờ một điều kiện cụ thể (hiện ra, bấm được, có chữ...). Cách được khuyến nghị.

### Cách tệ: time.sleep
Giải thích từng dòng:
• Trang dynamic_loading/1: bấm nút Start, thanh loading chạy khoảng 5 giây rồi hiện "Hello lab!".
• #start button: nút nằm trong phần tử id="start".
• time.sleep(10): luôn đứng chờ đủ 10 giây, dù chữ đã hiện sau 5 giây. 100 test như vậy lãng phí gần 10 phút.
• Nếu server chậm hơn 10 giây, test vẫn hỏng.
Kết luận: sleep vừa chậm vừa không chắc chắn.
~~~python
import time
driver.get("http://localhost:3131/dynamic_loading/1")
driver.find_element(By.CSS_SELECTOR, "#start button").click()
time.sleep(10)
print(driver.find_element(By.ID, "finish").text)
~~~

### Implicit wait: chờ ngầm cho mọi lần tìm
Giải thích từng dòng:
• implicitly_wait(10): từ giờ, mỗi lần find_element không thấy phần tử, Selenium thử lại liên tục tối đa 10 giây.
• dynamic_loading/2: phần tử #finish chỉ được thêm vào trang sau khi tải xong.
• find_element(By.ID, "finish"): chờ đến khi phần tử xuất hiện rồi đọc chữ. In ra: Hello lab!
Hạn chế: implicit wait chỉ chờ phần tử "có mặt", không chờ nó "hiện ra" hay "bấm được". Không nên trộn implicit và explicit wait trong cùng dự án vì thời gian chờ có thể cộng dồn khó đoán.
~~~python
driver = webdriver.Chrome()
driver.implicitly_wait(10)
driver.get("http://localhost:3131/dynamic_loading/2")
driver.find_element(By.CSS_SELECTOR, "#start button").click()
print(driver.find_element(By.ID, "finish").text)
~~~

### Explicit wait: chờ đúng điều kiện cần
Giải thích từng dòng:
• WebDriverWait: "đồng hồ chờ" của Selenium.
• expected_conditions as EC: bộ điều kiện có sẵn, đặt tên ngắn là EC.
• WebDriverWait(driver, 10): chờ tối đa 10 giây.
• element_to_be_clickable((By..., "...")): chờ nút bấm được rồi trả phần tử, ta click luôn. Chú ý có HAI cặp ngoặc vì locator là một bộ (By, giá trị).
• visibility_of_element_located: chờ phần tử hiện ra trên màn hình (ở trang 1, #finish có sẵn nhưng bị ẩn).
• Xong sớm thì đi tiếp ngay, không lãng phí. Kết quả: OK: Hello lab!
~~~python
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

driver.get("http://localhost:3131/dynamic_loading/1")
wait = WebDriverWait(driver, 10)
wait.until(EC.element_to_be_clickable((By.CSS_SELECTOR, "#start button"))).click()
finish = wait.until(EC.visibility_of_element_located((By.ID, "finish")))
assert finish.text == "Hello lab!"
print("OK:", finish.text)
~~~

### Các điều kiện EC hay dùng
Giải thích từng dòng:
• presence_of_element_located: phần tử có trong HTML (có thể đang ẩn).
• visibility_of_element_located: phần tử có và đang hiện.
• invisibility_of_element_located: chờ phần tử biến mất, ví dụ biểu tượng loading.
• text_to_be_present_in_element: phần tử chứa chữ mong muốn.
• url_contains: địa chỉ trang chứa đoạn chữ.
• title_is: tiêu đề trang bằng đúng chữ.
• alert_is_present: có hộp thoại alert hiện lên (bài 8).
~~~python
wait.until(EC.presence_of_element_located((By.ID, "content")))
wait.until(EC.visibility_of_element_located((By.ID, "flash")))
wait.until(EC.invisibility_of_element_located((By.ID, "loading")))
wait.until(EC.text_to_be_present_in_element((By.ID, "finish"), "Hello lab"))
wait.until(EC.url_contains("/secure"))
wait.until(EC.title_is("UI Lab Mầm"))
wait.until(EC.alert_is_present())
~~~

### Lỗi thường gặp
• Lỗi 1: điều kiện không thành sự thật trong thời gian chờ. Thông báo thường trống. Kiểm tra locator, kiểm tra điều kiện có hợp lý không, sau đó mới cân nhắc tăng thời gian chờ.
• Lỗi 2: phần tử bạn giữ trong biến đã bị trang vẽ lại (refresh, chuyển trang, danh sách tải lại). Cách sửa: tìm lại phần tử ngay trước khi dùng, đừng giữ biến quá lâu.
• Lỗi 3: quên cặp ngoặc thứ hai: EC.visibility_of_element_located(By.ID, "x") sai, phải là EC.visibility_of_element_located((By.ID, "x")).
~~~text
selenium.common.exceptions.TimeoutException: Message:
selenium.common.exceptions.StaleElementReferenceException: Message: stale element reference: stale element not found
TypeError: __init__() takes 2 positional arguments but 3 were given
~~~

PRACTICE: Viết script cho trang http://localhost:3131/dynamic_controls: bấm nút "Remove", dùng explicit wait chờ dòng chữ "Removed in lab" xuất hiện trong phần tử id="message", rồi in ra. Không dùng time.sleep.
Q: Cách chờ nào được khuyến nghị nhất trong test Selenium?
- time.sleep với số giây lớn
+ Explicit wait với WebDriverWait và điều kiện cụ thể
- Không chờ gì cả
Q: Lỗi StaleElementReferenceException thường do đâu?
- Sai cú pháp CSS selector
+ Phần tử đã bị trang vẽ lại sau khi bạn tìm thấy nó
- Mất kết nối mạng
Q: Điểm khác chính giữa presence_of_element_located và visibility_of_element_located là gì?
+ presence chỉ cần phần tử có trong HTML, visibility đòi hỏi phần tử đang hiện ra
- Hai điều kiện giống hệt nhau

## LESSON selenium-06 | Viết test với pytest: fixture, headless và chụp ảnh khi lỗi

### pytest là gì?
Script ở các bài trước chạy được nhưng chưa phải "bộ test": không có báo cáo pass/fail, không tự dọn dẹp.
pytest là "giám thị phòng thi": tìm các bài test, chạy từng bài, chấm điểm và báo cáo.
Quy tắc đặt tên để pytest tự tìm thấy:
• Tên file bắt đầu bằng test_ (ví dụ test_login.py).
• Tên hàm test bắt đầu bằng test_ (ví dụ def test_login_ok():).
Giải thích: hai hàm test đơn giản, mỗi hàm có một assert. Lưu vào test_vidu.py rồi chạy pytest -v, kết quả: 2 passed.
~~~python
def test_cong():
    assert 1 + 1 == 2

def test_chuoi():
    assert "secure" in "http://localhost:3131/secure"
~~~

### Bước 1: Tạo fixture driver trong conftest.py
Fixture là phần "chuẩn bị và dọn dẹp" dùng chung, giống người trực phòng mở cửa trước giờ học và khóa cửa sau giờ học.
Giải thích từng dòng:
• conftest.py: file đặc biệt, pytest tự đọc, fixture trong đó dùng được cho mọi file test cùng thư mục.
• @pytest.fixture: đánh dấu hàm driver là một fixture.
• ChromeOptions(): bộ tùy chọn cho Chrome.
• --headless=new: chạy Chrome ẩn, không hiện cửa sổ (nhanh, dùng được trên server CI). Xóa dòng này nếu muốn nhìn thấy.
• --window-size=1280,800: đặt kích thước cửa sổ để giao diện ổn định khi chạy ẩn.
• yield drv: đưa driver cho test dùng. Code sau yield chạy SAU khi test xong, dù pass hay fail.
• drv.quit(): luôn đóng trình duyệt.
~~~python
import pytest
from selenium import webdriver

@pytest.fixture
def driver():
    options = webdriver.ChromeOptions()
    options.add_argument("--headless=new")
    options.add_argument("--window-size=1280,800")
    drv = webdriver.Chrome(options=options)
    yield drv
    drv.quit()
~~~

### Bước 4: Tự chụp màn hình khi test fail
Thêm vào cuối conftest.py:
Giải thích từng dòng:
• pytest_runtest_makereport: "móc" (hook) mà pytest gọi sau mỗi giai đoạn của test.
• outcome = yield ... get_result(): lấy kết quả của giai đoạn vừa chạy.
• report.when == "call" and report.failed: chỉ xử lý khi phần thân test bị fail.
• item.funcargs.get("driver"): lấy driver mà test đó đang dùng.
• os.makedirs("screenshots", exist_ok=True): tạo thư mục screenshots nếu chưa có.
• save_screenshot(...): lưu ảnh tên theo tên test, ví dụ screenshots/test_login_sai_mat_khau.png.
Ảnh được chụp trước khi fixture quit trình duyệt, nên vẫn còn trang để chụp.
~~~python
import os

@pytest.hookimpl(hookwrapper=True)
def pytest_runtest_makereport(item, call):
    outcome = yield
    report = outcome.get_result()
    if report.when == "call" and report.failed:
        drv = item.funcargs.get("driver")
        if drv is not None:
            os.makedirs("screenshots", exist_ok=True)
            drv.save_screenshot(f"screenshots/{item.name}.png")
~~~

### Lỗi thường gặp
• Lỗi 1: pytest không tìm thấy test. Kiểm tra tên file bắt đầu bằng test_ và tên hàm bắt đầu bằng test_, và bạn đang đứng đúng thư mục.
• Lỗi 2: conftest.py đặt sai chỗ hoặc sai tên (phải đúng conftest.py, cùng thư mục hoặc thư mục cha của file test).
• Lỗi 3: chưa bật venv hoặc chưa cài pytest. Bật venv, hoặc chạy python -m pytest -v.

## LESSON selenium-07 | Page Object Model với Selenium

### Vì sao cần Page Object?
Khi có 50 test cùng đăng nhập, mỗi test lặp lại 3 dòng find_element giống nhau.
Một ngày lập trình viên đổi id="username" thành id="user-name": bạn phải sửa 50 chỗ.
Page Object Model (POM): mỗi trang web có một class riêng chứa locator và thao tác của trang đó.
• Giống tờ "hướng dẫn sử dụng" cho từng trang: test chỉ cần nói "đăng nhập với A, B".
• Đổi giao diện: sửa một chỗ trong class, 50 test vẫn chạy.
• Test đọc như kịch bản nghiệp vụ, dễ cho người khác review.

### Cấu trúc thư mục
Giải thích từng dòng:
• pages/: chứa các Page Object.
• __init__.py: file rỗng, đánh dấu pages là một "gói" Python để import được.
• login_page.py, secure_page.py: mỗi trang một file.
• tests/: chứa conftest.py (fixture driver) và các file test.
• requirements.txt: danh sách thư viện (pip freeze > requirements.txt).
Chạy pytest từ thư mục gốc selenium-hoc để Python tìm thấy gói pages (nếu báo lỗi import, chạy python -m pytest -v).
~~~text
selenium-hoc/
├── pages/
│   ├── __init__.py
│   ├── login_page.py
│   └── secure_page.py
├── tests/
│   ├── conftest.py
│   └── test_login_pom.py
└── requirements.txt
~~~

### Viết class LoginPage
Giải thích từng dòng:
• class LoginPage: khuôn mẫu cho trang đăng nhập.
• USERNAME = (By.ID, "username"): locator lưu thành một bộ, đặt tên viết hoa cho dễ nhận ra.
• __init__(self, driver): chạy khi tạo đối tượng, giữ driver và tạo đồng hồ chờ 10 giây.
• open(): mở trang, return self để có thể viết liền LoginPage(driver).open().
• login(...): gõ username, password, bấm nút. Dấu * trong find_element(*self.USERNAME) "mở bộ" thành 2 tham số By.ID, "username".
• flash_text(): chờ thông báo hiện rồi trả về chữ.
~~~python
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

class LoginPage:
    URL = "http://localhost:3131/login"
    USERNAME = (By.ID, "username")
    PASSWORD = (By.ID, "password")
    SUBMIT = (By.CSS_SELECTOR, "button[type='submit']")
    FLASH = (By.ID, "flash")

    def __init__(self, driver):
        self.driver = driver
        self.wait = WebDriverWait(driver, 10)

    def open(self):
        self.driver.get(self.URL)
        return self

    def login(self, username, password):
        self.driver.find_element(*self.USERNAME).send_keys(username)
        self.driver.find_element(*self.PASSWORD).send_keys(password)
        self.driver.find_element(*self.SUBMIT).click()

    def flash_text(self):
        return self.wait.until(EC.visibility_of_element_located(self.FLASH)).text
~~~

### Test dùng LoginPage
Giải thích từng dòng:
• from pages.login_page import LoginPage: lấy class từ file pages/login_page.py.
• LoginPage(driver).open(): tạo Page Object và mở trang.
• page.login(...): một dòng thay cho 3 dòng tìm và gõ.
• assert ... in page.flash_text(): phần kiểm tra vẫn nằm trong test, Page Object chỉ lo "làm".

## LESSON selenium-08 | Dropdown, alert, iframe và nhiều cửa sổ

### Dropdown với Select
Giải thích từng dòng:
• Select: lớp hỗ trợ riêng cho thẻ select (danh sách thả xuống).
• Select(driver.find_element(...)): bọc phần tử select để dùng các hàm chọn.
• select_by_visible_text("Option 1"): chọn theo chữ người dùng nhìn thấy.
• first_selected_option.text: đọc lựa chọn hiện tại. In ra: Option 1
• select_by_value("2"): chọn theo thuộc tính value trong HTML. In ra: Option 2
• dropdown.options: danh sách mọi lựa chọn. In ra: ['Choose', 'Option 1', 'Option 2']
Lưu ý: Select chỉ dùng cho thẻ select thật. Dropdown "tự chế" bằng div thì bấm mở rồi bấm vào mục như phần tử thường.
~~~python
from selenium.webdriver.support.ui import Select

driver.get("http://localhost:3131/dropdown")

dropdown.select_by_visible_text("Option 1")
print(dropdown.first_selected_option.text)
dropdown.select_by_value("2")
print(dropdown.first_selected_option.text)
print([o.text for o in dropdown.options])
~~~

### Hộp thoại alert, confirm, prompt
Giải thích từng dòng:
• Bấm nút "Click for JS Alert" để bật hộp thoại của trình duyệt (không phải HTML, nên không find_element được).
• EC.alert_is_present(): chờ hộp thoại xuất hiện và trả về đối tượng alert.
• alert.text: đọc chữ trong hộp thoại. In ra: Lab alert
• alert.accept(): bấm OK. Muốn bấm Cancel thì dùng alert.dismiss().
• #result: dòng kết quả trên trang. In ra: Lab alert accepted
• Với prompt: send_keys gõ chữ vào hộp thoại rồi accept. In ra: Lab input: Xin chao
~~~python
driver.get("http://localhost:3131/javascript_alerts")

alert.accept()
print(driver.find_element(By.ID, "result").text)
driver.find_element(By.XPATH, "//button[text()='Click for JS Prompt']").click()

prompt.send_keys("Xin chao")
prompt.accept()
print(driver.find_element(By.ID, "result").text)
~~~

### Nhiều tab và cửa sổ
Giải thích từng dòng:
• current_window_handle: "mã số" của cửa sổ hiện tại, lưu lại để quay về.

• driver.close(): đóng tab hiện tại (khác quit là đóng tất cả).
• switch_to.window(goc): quay về tab gốc. In ra: UI Lab Mầm
~~~python

driver.switch_to.window(goc)
print(driver.title)
~~~

## LESSON selenium-09 | Stale element và chờ theo điều kiện nghiệp vụ

### Node mới không phải phần tử cũ
Danh sách lớp giả định Bụi Lụa render lại sau lọc. WebElement cũ có thể stale dù control trông không đổi; giữ locator ổn định để tìm lại, không cache cả danh sách qua lần render.
~~~python
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
row=(By.CSS_SELECTOR,'[data-test=class-row]')
old=driver.find_element(*row)
driver.find_element(By.ID,'apply-filter').click()
WebDriverWait(driver,10).until(EC.staleness_of(old))
~~~

### Chờ trạng thái mà thao tác sau cần
Sau khi DOM thay, chờ nội dung kết quả đúng bộ lọc thay vì chỉ presence. Fixture lab ghi tổng số lớp vào data-test count; điều kiện text giúp loại việc đọc dữ liệu cũ.
~~~python
count=(By.CSS_SELECTOR,'[data-test=result-count]')
WebDriverWait(driver,10).until(EC.text_to_be_present_in_element(count,'3 lớp'))
rows=driver.find_elements(*row)
assert len(rows)==3
~~~

### Hạn chế retry ở ranh giới có hiểu biết
Tìm lại phần tử đọc sau stale khác với bấm lại đăng ký. Thao tác ghi đã có thể đến server trước exception; kiểm trạng thái và mã chống lặp theo lab, không catch mọi exception rồi click tiếp.
~~~text
Đọc nhãn sau render -> chờ điều kiện, tìm lại
Click tạo đăng ký -> kiểm trạng thái trước retry
Timeout do selector sai -> sửa selector, không tăng retry
Không dùng while True cho stale.
~~~

### Bẫy snapshot danh sách WebElement
Một list WebElement không tự cập nhật khi DOM đổi. Nếu mục tiêu là số lượng theo bộ lọc, tìm lại sau điều kiện hoàn tất và assert expected, không dùng len của list cũ.

### Đưa race vào fixture có kiểm soát
Lab trì hoãn render và thay node nhưng giữ text để phơi bày test đang đọc cũ. Lưu timeline lọc/render/assert; một lần chạy nhanh không đủ xác nhận đã sửa race.

PRACTICE: Viết ca lọc thay DOM, một ca giữ text giống nhưng node mới, một ca click ghi bị chậm. Nộp locator, điều kiện chờ và bằng chứng không retry thao tác ghi mù.
Q: Stale element nghĩa là gì?
+ Tham chiếu phần tử không còn gắn DOM hiện tại
- Locator luôn sai cú pháp
- Mạng luôn bị tắt
Q: Retry click mù sau stale có nguy cơ gì?
+ Lặp thao tác đã có tác dụng
- Luôn an toàn
- Tự tạo idempotency

## LESSON selenium-12 | Tệp tải về, cấu hình và dữ liệu kiểm soát

### Tệp tải cần thư mục mỗi ca
Form xuất báo cáo của xưởng giả định Nếp Vạt tạo CSV. Dùng tmp_path của pytest tránh file cũ khiến test xanh; ChromeOptions phải được cấu hình trước khi tạo driver.
~~~python
options=webdriver.ChromeOptions()
options.add_experimental_option('prefs',{
 'download.default_directory':str(tmp_path.resolve()),
 'download.prompt_for_download':False
})
driver=webdriver.Chrome(options=options)
~~~

### Đợi hoàn tất chứ không chỉ nhìn tên
File đang tải có thể có đuôi tạm hoặc chưa đủ dữ liệu. Lab dùng tên cố định report.csv và chờ không còn crdownload; cơ chế cụ thể phụ thuộc browser, không dùng sleep cứng làm bằng chứng.
~~~python
from pathlib import Path
folder=Path(tmp_path)
def complete(_):
 p=folder/'report.csv'
 return p.exists() and not list(folder.glob('*.crdownload'))
WebDriverWait(driver,10).until(complete)
~~~

### Kiểm nội dung theo hợp đồng CSV
Đọc UTF-8 theo quy tắc lab và kiểm cột, số dòng, giá trị tổng; không tự mở file thành lệnh hay tin đuôi file. File remote cần cơ chế artifact riêng, không giả định nó nằm máy test.

~~~python
import csv
with (folder/'report.csv').open(encoding='utf-8',newline='') as f:

assert len(rows)==3
assert set(rows[0])=={'id','qty'}
assert sum(int(x['qty']) for x in rows)==7
~~~

Base URL và đường dẫn artifact được nhận từ cấu hình lab, kiểm allowlist localhost/example.com và thư mục trước chạy. Không đưa credential vào pytest param id hoặc tên file.

### Thử file sai để chứng minh assertion
Fixture xuất thiếu dòng, sai encoding hoặc sai tổng phải làm ca đỏ với lỗi rõ. Một kiểm exists chỉ phát hiện không có file, không chứng minh nội dung đúng.

### Page Object nhỏ theo hành vi
Hàm submit chỉ thao tác và chờ kết quả thuộc trang, không nuốt exception. Test giữ assertion nghiệp vụ để người review đọc được mục tiêu; locator dựa id lab đã thống nhất.
~~~python
class EnrollmentPage:
 def __init__(self,driver): self.driver=driver
 def enter_name(self,value):
  field=self.driver.find_element(By.ID,'student-name')
  field.clear();field.send_keys(value)
 def submit(self):
  self.driver.find_element(By.ID,'enroll').click()
  return WebDriverWait(self.driver,10).until(
   EC.visibility_of_element_located((By.ID,'result'))).text
~~~

~~~python
def test_enroll_with_vietnamese_name(driver):

~~~
